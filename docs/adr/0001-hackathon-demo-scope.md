# Hackathon 展示范围：YouTube 导航与现场 pitch 检测

本次 Hackathon 的可展示 MVP 聚焦两段真实闭环：先用不同类型的 YouTube 视频展示语义信号与视频跳转，再用 MacBook 内置麦克风对现场项目 pitch 做实时检测。浏览器会议采集暂不交付；未完成能力在展示中明确标注。这个取舍把一天的开发与验证时间集中在观众能直接看到并检查原文的效果上，避免三种采集入口都只完成表面流程。

实现顺序先从 YouTube 视频热力图的完整闭环开始；现场采集作为下一阶段，保留在演示目标中。ASR 先用现有 Gemini 凭证做 smoke test，更多 speech-to-text 服务的准确性、延迟和费用比较进入 backlog。

YouTube 演示使用事先挑选、已验证有完整时间戳字幕的三条不同类别视频。真实分析结果可在台前预计算并缓存，界面标明“已预分析”；每条视频至少核对两个热力图高峰。现场使用 MacBook 内置麦克风持续采集多个项目 pitch，默认根据静音与说话内容推测项目边界，并允许手动切换；项目段与总时间轴的关系见 ADR 0003。术语堆砌、空泛宣传、技术细节表达、目标受众描述和有趣表达是候选探针方向，最终组合尚未确定。观众现场自定义探针属于加分环节，不作为 MVP 必达验收。

YouTube 探针有效性的展示方式是点击热力图的高值区间，同时显示原句并跳到命中区间前几秒播放，让观众对照探针描述检查是否吻合。

现场采集停止后，由用户选择保存或删除转写文本、项目段与读数；默认不保存原始音频。

YouTube 热力图的第一阶段沿用参考项目的形态：视频留在 YouTube 原页面，CueWave 在 Chrome 侧边栏展示探针轨道、热力图和证据原句；独立大屏放到第二阶段。第一阶段使用 YouTube 原生字幕与侧边栏证据，不要求自有视频底部字幕 overlay。用户确认探针后手动点击“分析视频”；精选视频应自动获取完整时间戳字幕，SRT/VTT 导入作为明确标注的后备。现场阶段展示当前读数和持续增长的时间轴，并沿用相同探针卡片、颜色和证据交互。现场命中可以有醒目的视觉提示，默认无提示音，避免声音再次进入麦克风。现场读数以最终字幕产生后约 15 秒内出现为初始验收目标，实际端到端延迟需实测；当前估计主要瓶颈在语音转文字。

实现可复用 youtube-digest 的字幕获取、侧边栏宿主和视频跳转等核心能力，但 CueWave 重新设计自己的界面风格。第一轮开发可使用测试视频和临时探针验证通用闭环；它们不自动成为最终演示素材。各探针的热点独立排名，每条视频选定探针后验证其最高的两个有效热点。

YouTube 播放器进度条上方的横向直方图是关键视觉参考：它沿视频时间分布显示语义信号。多条启用探针用不同半透明颜色叠加，选中探针时突出它；直方图只在鼠标悬停进度条时显示。侧边栏保留多轨详情和证据。

YouTube 长视频的分析结果逐批显示，未完成区间与有效结果明确区分；演示使用的探针含义可在上台前完成歧义检查、选择并缓存。

现场另以讲话结束后约 8 秒内出现读数为端到端目标，需实测验证。每条精选视频点击自动排序最高的两个有效热点核对原片，不在同一视频中另行挑选好看的命中。开启现场采集前提醒参与者，投屏持续显示正在采集 MacBook 麦克风。

MVP 只需在演示者的 MacBook 上运行，不要求分发扩展包。现场转写允许使用已告知参与者的云端 ASR，但选型需权衡中文及英文准确性、延迟和费用；另有一台 Ubuntu 22.04、RTX 3090 24GB 工作站可作为候选算力。英文发言的字幕和证据保留英文原句，首版不强制翻译。
